InstallerLab / MSI builder
Visual MSI authoring for Windows developers

Build a real MSI from the same FSS project you use for Setup EXE and Bundle.

InstallerLab v2 reuses application metadata, files, destination, registry, shortcuts and other supported project rules, then sends the MSI plan to its WiX-based backend. Normal authoring does not require maintaining hand-written WiX XML.

Why MSI is a separate output, not a separate project

Reuse project metadata

Name, version, publisher and destination come from the same FSS used by the other InstallerLab backends.

Reuse application payload

Files and supported directory rules are planned from the same project instead of maintained in a second MSI definition.

Support Windows deployment

The resulting package is a real Windows Installer MSI suitable for msiexec and managed deployment scenarios.

x64 installation support

InstallerLab v2 includes improved x64 Program Files handling in the MSI backend.

Embedded cabinet media

The v2 backend embeds cabinet media in the generated MSI rather than leaving an external payload CAB.

Directory permissions

Supported FSS directory permissions can be translated into MSI authoring when required by the project.

A pure MSI intentionally does not perform InstallerLab's prerequisite chain. Bundle exists for that job.

Useful MSI commands

Silent install

msiexec /i "MyApplication.msi" /qn /norestart /L*v "install.log"

Silent uninstall

msiexec /x "MyApplication.msi" /qn /norestart /L*v "uninstall.log"

WiX requirement

InstallerLab itself can run without WiX, but MSI and Bundle builds require the WiX CLI. Bundle additionally uses the BootstrapperApplications and Util extensions documented in the Bundle guide.

MSI builder FAQ

Does InstallerLab create a real MSI?

Yes. The MSI backend builds a Windows Installer package through WiX.

Do I need to write WiX XML?

Not for normal InstallerLab authoring. The project is defined visually/FSS and translated for the backend.

Are prerequisites included in the pure MSI?

No. Use the WiX Burn Bundle target when prerequisites must run before the main MSI.

Can I import an Inno Setup project and then create MSI?

InstallerLab v2 can import supported ISS sections to FSS. After review and analysis, compatible project configuration can be used by the MSI backend.

Use MSI when Windows Installer is the destination, not the authoring experience.

Keep the project in FSS and let InstallerLab handle the WiX backend.
