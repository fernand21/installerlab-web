What a Bundle solves

Install prerequisites first

Use Bundle when the product needs runtimes or other EXE/MSI packages before the main application package.

Keep one product definition

The FSS remains the project. Bundle does not require you to maintain a separate product definition just to create a bootstrapper.

Build the main MSI automatically

The Bundle flow generates the internal MSI and then uses WiX Burn to create the final executable chain.

Order stays explicit

Prerequisites are processed before the main MSI according to the project chain, making dependency order visible instead of hidden.

One EXE for the user

The final Bundle is a single executable bootstrapper even when the installation flow contains multiple packages.

InstallerLab branding

InstallerLab v2 uses WixStandardBootstrapperApplication with InstallerLab-specific Bundle branding.

WiX requirements for Bundle builds

InstallerLab can run without WiX, but MSI and Bundle creation require the WiX CLI and the extensions used by the Bundle backend.

dotnet tool install --global wix
wix extension add WixToolset.BootstrapperApplications.wixext --global
wix extension add WixToolset.Util.wixext --global
The normal InstallerLab Setup EXE is the recommended download when you want the installation process to prepare the required packaging toolchain.

WiX Burn Bundle FAQ

Does InstallerLab create a real WiX Burn Bundle?

Yes. InstallerLab v2 has a separate Bundle backend that generates the main MSI and builds the final bootstrapper through WiX Burn.

Can prerequisites be EXE or MSI packages?

Yes. The current Bundle flow supports local EXE/MSI prerequisite packages in the project chain.

Does Bundle replace MSI?

No. Bundle wraps an installation chain around the main MSI. Use pure MSI when you only need the Windows Installer package; use Bundle when prerequisites must run first.

Do I need a second InstallerLab project?

No. The same editable FSS remains the source of truth.
