Why analyze the project first?

Catch configuration mistakes earlier

Validation is cheaper before packaging than after a failed build or a broken installer test.

Keep warnings visible

Not every issue should block a build. Analyzer results can distinguish problems that need attention from items that should simply be reviewed.

Check compatibility before changing backend

A project can target different output types, and some rules do not behave identically across Setup EXE, MSI and Bundle.

Use it after ISS import

When migrating from Inno Setup, run FSS Analyzer on the imported project before the first build.

Keep the project inspectable

FSS remains plain text, so analyzer findings refer to a project you can inspect, version and edit directly.

Reduce trial-and-error packaging

The goal is to make the project itself trustworthy before the heavier packaging stages begin.

Recommended workflow

StepAction
1Create, edit or import the FSS project.
2Run FSS Analyzer and review errors, warnings and compatibility findings.
3Correct the project while it is still just editable text.
4Build Setup EXE, MSI, Bundle or another supported target.
5Test the final installer on a clean Windows environment.

Useful after migration

If you used the ISS → FSS importer, analyze the converted project before relying on it for a release build.

Useful before Bundle

Bundle introduces prerequisite chaining around the main MSI, so validating the project before the chain is generated keeps troubleshooting focused.

FSS Analyzer FAQ

Does Analyzer replace testing the installer?

No. It validates the project before packaging, but the generated installer still needs real installation and uninstallation testing.

Can Analyzer be used with imported projects?

Yes. It is especially useful after ISS → FSS migration because the converted project should be reviewed before release.

Is FSS a binary project format?

No. FSS is InstallerLab's lightweight editable text project format.

Validate first. Package second.

FSS Analyzer turns project validation into a normal part of the InstallerLab v2 workflow.
