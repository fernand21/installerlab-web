Turn a URL or local HTML app into a Windows desktop application — then deploy it from the same project.

Web-to-EXE is a first-class InstallerLab project type. Define a remote URL or a local web application, configure the Windows WebView2 host, and use the same editable FSS project to create a single-file Web-to-EXE application, Setup EXE, MSI or WiX Burn Bundle.

One project, two jobs: create the desktop app and create its installer.

Remote website

Point the project at a web URL. InstallerLab writes the WebView2 host configuration and prepares the Windows application.

Local HTML application

Use a local application folder containing index.html. The local web payload becomes part of the generated Windows application.

Single-file Web-to-EXE

The prepared WebView2 application can be wrapped into a single-file output through InstallerLab's portable engine.

Installer targets

The same WebToExe project can generate Setup EXE, MSI or Bundle without first exporting to another authoring tool.

Self-contained runtime

WebView2 is packaged with the generated application. The end user does not need to install WebView2 separately.

Project-aware output

InstallerLab disables classic Portable and B4J Portable targets for WebToExe projects and exposes only the targets that match this project type.

Online or fully local/offline.

Online URL mode

Point WebToExe at a live URL. The Windows app loads the current online application, so server-side updates appear without rebuilding the desktop package.

Local HTML mode

Package the HTML, CSS, JavaScript, images and other local assets with the Windows application. The UI can run without Internet access when the application itself does not depend on remote APIs or resources.

A project can therefore choose between a live online application and a self-contained local web application. Local mode removes the dependency on a website being reachable; only intentionally remote services remain network-dependent.

Why this is different from a “Web Installer”.

A traditional web installer is an installer bootstrapper that downloads installation resources from the Internet. Web-to-EXE solves a different problem: it turns the web application itself into a Windows desktop application and then packages that application.

Web-to-EXE FAQ

Does InstallerLab just create a shortcut to a website?

No. The v4 workflow prepares a Windows WebView2 host and its configuration, then builds the requested Windows artifact.

Can I package local HTML instead of a public URL?

Yes. A local web application folder can be used for PRO WebToExe projects.

Can one project generate both the app and its installer?

Yes. That is the key v4 workflow: the WebToExe project defines the web application and also drives its supported deployment targets.

Does the target PC need WebView2 installed?

No. InstallerLab v4 packages WebView2 as self-contained runtime content with the generated application, so no separate WebView2 installation is required.
