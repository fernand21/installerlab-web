Why import instead of starting again?

Preserve useful project structure

The importer converts supported ISS sections into InstallerLab's own FSS representation so existing work can become the starting point.

Move into a visual workflow

After import, the resulting FSS can be opened in InstallerLab and edited through the visual project panels or directly as text.

Keep a lightweight project file

FSS is plain text and remains the durable project definition instead of relying on bulky generated build-state directories.

Analyze before building

Run FSS Analyzer after migration to surface errors, warnings or compatibility issues before packaging.

Target more than one package format

The migrated FSS can participate in InstallerLab's Setup EXE, MSI, Bundle and other supported build workflows.

Migration remains inspectable

The result is not hidden in a proprietary binary project. You can review the generated FSS and adjust anything that needs manual attention.

ISS and FSS are not the same format

InstallerLab does not pretend that an Inno Setup script and an FSS project are identical. The importer translates the sections and rules that InstallerLab supports; the resulting FSS should be reviewed and tested before release.

ISS → FSS importer FAQ

Does InstallerLab import every Inno Setup feature?

No. The importer converts supported sections and rules. Unsupported or tool-specific behavior may require manual review or adaptation.

Does the imported project stay editable?

Yes. The output is an InstallerLab FSS text project that can be edited visually or directly.

Can I create a Bundle after importing?

Yes, when the resulting FSS contains supported configuration for that build target. Bundle creation uses InstallerLab's WiX Burn backend.

Is InstallerLab an Inno Setup clone?

No. InstallerLab is an independent tool with its own FSS format, visual workflow and packaging backends.
