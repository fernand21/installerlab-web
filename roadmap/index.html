Public development roadmap

One FSS project. More ways to ship Windows software.

InstallerLab is evolving around one principle: developers should describe what their application needs once, then let specialized backends translate that intent into the right Windows distribution format.

Visual when you want speed. FSS when you want control. One project when you want EXE, MSI, Portable, Bundle and eventually MSIX.
● Available now

Foundation already in InstallerLab

The current architecture already proves the multi-backend model.

Setup EXE + MSI from one project

The same InstallerLab project/FSS drives the normal Setup EXE workflow and the WiX-backed MSI workflow.

Editable FSS

Visual authoring does not hide the project. Developers can inspect and edit the declarative FSS source directly.

Windows integration

Files, folders, shortcuts, registry, file associations, Open With, context-menu actions, run actions and cleanup rules.

Portable and B4J workflows

Portable creation, plus a dedicated B4J Portable path that uses the developer's B4J and JDK toolchain.

● Next priorities

Deployment features developers use every day

The next phase focuses on capabilities that remove external setup work and make professional deployment easier.

Bundle / Bootstrapper

Chain prerequisites and the main package into one bootstrapper: .NET, VC++ Runtime, WebView2, Java, custom EXE/MSI packages and the final InstallerLab build.

Prerequisites V2

Detection by registry, file, version or Windows feature; embedded, URL or package sources; silent arguments, ordering and reboot handling.

Windows Services

Install, configure, start, stop, recover and remove Windows services from the same project.

Digital Signing

Use PFX or certificate-store certificates, timestamping and SHA-256 verification for application files and final packages.

● Planned

Automation, updates and advanced authoring

These features target teams, repeatable builds and deeper control without requiring a separate commercial edition for basic automation.

CLI + CI/CD

Build FSS projects from the command line and provide examples for GitHub Actions, GitLab CI, Azure DevOps and Jenkins.

InstallerLab Updater

Generate update metadata with version, URL, SHA-256, release notes, mandatory-update rules and minimum supported version.

SBOM generation

Generate SPDX or CycloneDX software bills of materials using package files, hashes, runtimes and declared dependencies.

Visual Dialog Editor

Customize installer dialogs with labels, buttons, images, checkboxes, text fields, progress controls and branded layouts.

● Future backend

MSIX from the same complete FSS project

MSIX is planned as another InstallerLab backend, not as an MSI-to-MSIX conversion. The goal is to translate the same FSS model directly into an MSIX package whenever the project is compatible.

FSS → MSIX

Reuse Setup, Files, Icons, Registry and other shared project data, with an optional [MSIX] section only for package-specific identity, capabilities and assets.

Compatibility analysis

Classify each FSS directive as compatible, adaptable or unsupported before building, instead of silently dropping behavior.

Package Identity

Explore Windows package identity for scenarios where developers want modern Windows integration without replacing their entire EXE/MSI installation model.

MSIX / MSIXBundle

Prepare package layout, manifest, assets and architecture-specific outputs, then use the Windows packaging toolchain as the backend.

The direction

FSS describes developer intent. Each backend decides how that intent should be represented in its native package format.

project.fss │ └── InstallerLab model ├── Setup EXE backend ├── MSI / WiX backend ├── Portable backend ├── Bundle backend └── MSIX backend (planned)
Roadmap note: this page describes development direction, not fixed release dates or contractual commitments. Priorities can change based on testing, Windows platform changes and developer feedback. The current intention is to keep the core installer-building workflow free; optional supporter/PRO activation continues to support development and currently unlocks Portable creation and PRO themes.

Hoja de ruta pública

Un proyecto FSS. Más formas de distribuir software para Windows.

InstallerLab evoluciona alrededor de una idea: el desarrollador describe una sola vez lo que necesita su aplicación y cada backend especializado traduce esa intención al formato de distribución adecuado.

Visual cuando quieres rapidez. FSS cuando quieres control. El mismo proyecto cuando quieres EXE, MSI, Portable, Bundle y, más adelante, MSIX.
● Disponible ahora

La base que ya existe

La arquitectura actual ya demuestra el modelo de múltiples backends.

Setup EXE + MSI desde un proyecto

El mismo proyecto/FSS alimenta el Setup EXE y el flujo MSI basado en WiX.

FSS editable

La edición visual no oculta el proyecto: el desarrollador puede revisar y editar directamente el FSS.

Integración con Windows

Archivos, carpetas, accesos directos, registro, asociaciones, Abrir con, menús contextuales, acciones y limpieza.

Portable y B4J

Creación de Portables y un flujo B4J Portable dedicado que utiliza el toolchain B4J/JDK del desarrollador.

● Próximas prioridades

Funciones de despliegue que los desarrolladores usan a diario

La siguiente fase busca eliminar trabajo externo y facilitar instalaciones profesionales.

Bundle / Bootstrapper

Encadenar prerrequisitos y el paquete principal: .NET, VC++ Runtime, WebView2, Java, EXE/MSI personalizados y el build final.

Prerequisites V2

Detección por registro, archivo, versión o Windows Feature; fuentes embebidas, URL o paquetes; argumentos silenciosos, orden y reinicios.

Windows Services

Instalar, configurar, iniciar, detener, recuperar y eliminar servicios de Windows desde el mismo proyecto.

Firma digital

Certificados PFX o del almacén de Windows, timestamp y verificación SHA-256 para archivos y paquetes finales.

● Planificado

Automatización, actualizaciones y autoría avanzada

Funciones dirigidas a equipos, builds repetibles y mayor control sin convertir la automatización básica en una barrera.

CLI + CI/CD

Compilar proyectos FSS desde línea de comandos y ofrecer ejemplos para GitHub Actions, GitLab CI, Azure DevOps y Jenkins.

InstallerLab Updater

Generar metadatos de actualización con versión, URL, SHA-256, notas, reglas de actualización obligatoria y versión mínima.

Generación SBOM

Generar SPDX o CycloneDX usando archivos del paquete, hashes, runtimes y dependencias declaradas.

Editor visual de diálogos

Personalizar diálogos con etiquetas, botones, imágenes, checkbox, campos de texto, progreso y diseños con marca propia.

● Backend futuro

MSIX desde el mismo FSS completo

MSIX se plantea como otro backend de InstallerLab, no como conversión MSI→MSIX. La meta es traducir directamente el mismo modelo FSS cuando el proyecto sea compatible.

FSS → MSIX

Reutilizar Setup, Files, Icons, Registry y los demás datos compartidos, con una sección [MSIX] opcional solo para identidad, capabilities y assets propios del formato.

Análisis de compatibilidad

Clasificar cada directiva FSS como compatible, adaptable o no soportada antes de compilar, sin perder comportamientos silenciosamente.

Package Identity

Explorar identidad de paquete de Windows para aplicaciones que quieren integración moderna sin reemplazar por completo su instalación EXE/MSI.

MSIX / MSIXBundle

Preparar layout, manifest, assets y salidas por arquitectura usando el toolchain de empaquetado de Windows como backend.

La dirección

FSS describe la intención del desarrollador. Cada backend decide cómo representarla correctamente en su formato nativo.

project.fss │ └── Modelo InstallerLab ├── Backend Setup EXE ├── Backend MSI / WiX ├── Backend Portable ├── Backend Bundle └── Backend MSIX (planificado)
Nota: esta hoja de ruta describe la dirección de desarrollo, no fechas comprometidas. Las prioridades pueden cambiar por pruebas, cambios de Windows y feedback. La intención actual es mantener gratuito el flujo principal de creación de instaladores; la activación opcional de soporte/PRO continúa ayudando al desarrollo y actualmente desbloquea la creación de Portables y los temas PRO.
